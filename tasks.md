# Очередь задач автономного агента

Демон (`daemon.ps1`) берёт **первую** невыполненную задачу, выполняет её целиком,
прогоняет `pnpm verify` и коммитит. Одна задача за запуск.

Пометки: `[ ]` не сделано · `[x]` сделано · `[!]` задача неверна или невыполнима,
рядом строка почему.

Задачи писать **проверяемыми**: у каждой должно быть видно, чем доказывается,
что она выполнена. «Улучшить экран» — не задача, «привести экран оплаты
к раскладке экрана заказа и проверить замером, что нет целей меньше 44px» —
задача.

## Интерфейс под iikoFront

Образец — `screens/orderscreen.tsx` и `screens/counterscreen.tsx`: плоские
панели, разделённые границей в пиксель, без внешних отступов; полоса функций
внизу; цель касания не меньше 44px по обеим сторонам.

- [x] Привести `screens/paymentscreen.tsx` к этой раскладке. Проверка:
      замером `getBoundingClientRect` на 1024x768 и 1366x768 нет ни одного
      интерактивного элемента меньше 44px и нет горизонтального скролла.
      Замер сделан не глазами, а `tools/measure-screen.mjs` (Chrome по CDP,
      три состояния экрана на обоих разрешениях) — им же меряются два
      следующих экрана. Полоса функций вынесена в общий
      `components/functionbar.tsx`: третьей копии не будет.

- [x] То же для `screens/cashscreen.tsx`. Три колонки (свод смены и свод ККТ,
      движения по ящику, операции клавиатурой), функции полосой внизу, отчёты
      в ней же — рядом с инкассацией «Закрыть смену» стоять не должна.
      Замерено `tools/measure-screen.mjs` потоком `cash`: четыре состояния
      на 1024x768 и 1366x768, целей меньше 44px и горизонтальной прокрутки нет.

- [x] То же для `screens/kitchenscreen.tsx`. Тикеты сеткой с переносом,
      станции колонкой справа со счётчиком, полоса функций внизу — только
      когда есть куда возвращаться. Читаемость с двух метров проверяется
      не глазами: в `tools/measure-screen.mjs` добавлен порог кегля внутри
      тикета (24px, главное — 30px), поток `kitchen` меряет четыре состояния
      на 1024x768 и 1366x768 — всё зелёное. Потоку нужен отдельный дев-сервер
      без узла, команда — в комментарии к потоку.

## Долги по коду

- [x] Тест на идемпотентность `fiscal_configure`: повторный вызов с теми же
      адресом и портом **не должен** пересобирать устройство, иначе на стенде
      обнуляется открытая смена. Сейчас это поведение держится только
      комментарием. Проверка: `cargo test --lib`.
      Тело команды вынесено в `configure(&FiscalState, ...)` — `tauri::State`
      в тесте не собрать. Четыре теста в `fiscal::commands::tests`: повтор
      настроек открытую смену не роняет, смена адреса и порта устройство
      пересобирают, род устройства с фронта не меняется.

- [ ] Прокинуть `taxSystem` и `defaultVat` из карточки ККМ в чек возврата
      (`state/checkout.tsx`, ветка `refund`). Сейчас в продаже они берутся
      из карточки, а в возврате — по умолчанию, и документы расходятся.
      Проверка: `pnpm verify` плюс тест на состав чека возврата.
