# Контракт между терминалом и узлом

`contract.json` — единственный источник истины для того, что обе стороны обязаны
понимать одинаково: коды прав, матрица роль→права, коды ошибок, имена
realtime-событий и шаблон имени комнаты.

Файл нейтрален по языку намеренно. Терминал написан на TypeScript, узел будет
на C# или C++ — общего кода у них нет и не будет, а матрица прав, продублированная
руками в двух языках, разъедется на первой же правке. Расхождение здесь означает
дыру в доступе: сотрудник получает право, которого у него быть не должно, либо
теряет то, которое нужно для работы.

## Как пользоваться

**Правится руками только `contract.json`.**

Со стороны TypeScript типы генерируются:

```bash
pnpm contracts:build    # contract.json → packages/shared-types/src/contract.generated.ts
pnpm contracts:check    # упасть, если сгенерированное отстало от json
```

`contracts:check` встроен в `pnpm typecheck`, поэтому забыть пересобрать нельзя.
Генератор попутно проверяет сам JSON: что все права из `rolePermissions`
и `overridablePermissions` объявлены в `permissions`, а все роли — в `roles`.

Со стороны узла файл читается как обычный JSON при старте. Захардкоживать
коды прав в C#-константах не нужно — при расхождении versions/списков сервис
должен падать на старте, а не отдавать неверные права в рантайме.

## Что внутри

| Ключ | Назначение |
|---|---|
| `version` | версия контракта. Растёт при несовместимом изменении |
| `conventions` | форматы денег, идентификаторов, времени, правило идемпотентности, шаблон имени комнаты |
| `roles` | роли персонала; обязаны совпадать с `StaffRole` в домене |
| `permissions` | все коды прав |
| `overridablePermissions` | права, которые можно получить разово подтверждением старшего |
| `rolePermissions` | матрица роль → права |
| `errorCodes` | машиночитаемые коды ошибок API |
| `eventTopics` | имена realtime-событий |

## Что контракт не описывает

Он про **словарь**, а не про поведение. Смысл прав, порядок проверок
на эндпоинте, устройство подтверждений — в `docs/access.md`. Перечень
эндпоинтов узла — в `docs/plan.md` §4.

Два места, где ошибиться легче всего:

- **`permission_denied` и `override_required` — разные ответы.** По первому
  терминал гасит кнопку, по второму открывает диалог ввода PIN. Свести их
  в один код нельзя.
- **События не переносят состояние.** В теле только идентификаторы: получатель
  перезапрашивает данные. Полный заказ в payload — прямой путь к рассинхрону
  между залом и кухней.
